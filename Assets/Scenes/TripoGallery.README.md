# TripoGallery

**The five Tripo characters, standing as an exhibition.** An arc of pedestals around the viewer,
each with a model, a caption and a slow turntable.

## What it does

One `GalleryRing` component reads `Assets/Tripo/TripoGalleryCatalog.asset` and builds the whole
ring — pedestal, model, label plate — for every catalogue entry. `[ExecuteAlways]`, so it is
visible in the Scene view without entering Play Mode, and everything it spawns is marked
`HideFlags.DontSave`, so the scene file stores the catalogue reference rather than a baked copy of
the hierarchy. Add a model to the catalogue and the scene is correct without being re-saved.

Each exhibit is scaled and seated from its **own renderer bounds**, not from its transform. Tripo
meshes carry no authored pivot, so the transform they arrive with says nothing about where their
feet are.

## What is missing

- **Never built or launched on the emulator.** This is the largest gap: the whole point of the
  decimation pass was device viability, and that has not been demonstrated.
- No interaction — you cannot walk up to a piece, select one, or hear anything.
- The five exhibits are all that exist; nothing generated by us is in the catalogue yet.
- The provenance fields (`tripoTaskId`, `tripoModelVersion`, `generatedOn`) are **empty** for all
  five, because muse-infinity never recorded them. Anything we generate will fill them.

## Notes

- **The captions are why the label is turned 180°.** A world-space `TextMeshPro` reads correctly
  when its own +Z points the *same way the viewer is looking*, i.e. away from the viewer. The
  exhibit root is already turned to face the viewer, so the extra 180 cancels back to identity.
  Do not copy that 180 to an unparented panel — it mirrors the text. (`TripoRuntime` proved this
  the hard way.)
- TMP's world-space `fontSize` is neither metres nor points. Measured here: `0.6` renders about
  16 mm of cap height; `0.085` is invisible.
- Stacking two text blocks means `centre = top - height/2`, because a `RectTransform`'s
  `localPosition` is its centre while `Top` alignment draws from the top edge. Getting that wrong
  renders the second block through the first — it did, twice. The plate is now one text block with
  `<size=175%>` on the first line, which cannot overlap itself.
- The catalogue doubles as the **rights record**. muse-infinity's `THIRD_PARTY_NOTICES.md` commits
  the project to recording generation account, date, ownership, terms and source inputs for every
  Tripo model, and its asset policy requires every likeness to stay labelled an AI interpretation.
  A note in a markdown file drifts from the asset; a field on the asset does not.
